Plan concret (pro, étape par étape)

Étape 1 — Vérifier que le front appelle bien l’API via le gateway (Nginx)
Objectif : depuis le navigateur sur http://marketech.local, un appel fetch("/api/health/") doit répondre 200.
Check rapide :
Dans DevTools (Network), tu dois voir :
GET http://marketech.local/api/health/ → 200 + JSON
Si tu veux qu’on le rende “visible” côté UI, on ajoute une page Vue “Status” qui affiche status: ok.

Étape 2 — Ajouter un endpoint “écriture DB” minimal (CRUD)
Tu as déjà un modèle Message. On va valider :
POST /api/messages/ crée une ligne en DB
GET /api/messages/ liste les messages
(optionnel) DELETE /api/messages/{id}
Puis on branche le front :
un petit formulaire (subject/body)
un bouton “Créer”
une liste qui se refresh
✅ Ça prouve :
Vue → Nginx gateway → backend → Postgres : OK en lecture/écriture.

Étape 3 — Vérifications “production readiness”
Avant VPS :
ALLOWED_HOSTS OK (déjà réglé)
logs lisibles (docker compose logs -f)
migrations/collectstatic au démarrage OK
healthcheck OK
pas de secrets committés (on nettoie .env, on garde .env.example)

Étape 4 — Déploiement sur VPS
Une fois l’app validée :
DNS (A/CNAME)
Nginx gateway sur VPS (80/443 + Let’s Encrypt)
docker compose sur VPS (app sur réseau proxy)
puis CI/CD (GitHub Actions / GitLab CI) qui déploie automatiquement
